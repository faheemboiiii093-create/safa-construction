# SAFA Construction website

This is a static HTML/CSS/JavaScript website. No frontend framework or package installation is required.

## Cinematic intro and 3D architecture

- `assets/safa-construction-logo-navy.png` is a transparent navy-theme derivative of the supplied logo: the roof is vivid warm gold and the charcoal mark/text are warm ivory for crisp contrast. The original `assets/safa-construction-logo.png` remains unchanged.
- The eight **What We Do** service cards and the **Our Work** concepts use pointer-responsive 3D tilt, image depth, and restrained scroll reveals. Clicking a service image, its **View in 3D** action, or any project card opens a wide cinematic Three.js gallery: one large gold-framed image floats before animated orbit rings and warm architectural lighting, rather than a row of preview cards. Browse all 14 current items with on-screen arrows or left/right keys; drag the active frame to rotate it. Each entry has its own title, description, image, and contact link. This presents illustrative photos in a 3D gallery, not as 3D building models. If WebGL or Three.js is unavailable, the selected image remains as a fallback.
- The eight-second intro runs once per browser tab session, starts muted, can be skipped, and can be replayed from the footer. Its transparent SAFA logo appears without a background card, centered above a separate animated **SAFA CONSTRUCTION** title. The logo/title arrive earlier, and the tagline, subtitle, and image note finish their reveal before the intro fades away. If intro audio is unavailable, the visual intro continues muted instead of getting stuck or showing an unnecessary audio-error prompt. With reduced motion enabled, the intro presents a static, visible logo and message for three seconds instead of hiding its content behind animation delays; the 3D hero animation also stops.
- On desktop, the native arrow cursor is hidden and replaced by a round, gold-outlined SAFA logo badge that follows the pointer. Text fields retain their text caret, and touch interactions remain unchanged.
- The Contact section’s email link opens the visitor’s email app with SAFA’s address, an enquiry subject, and a project-details template ready to edit; it does not send or store the message.
- The Contact section displays SAFA's configured phone number as a `tel:` link, so tapping it opens the device's available calling app with the number ready. The website cannot place a call without the visitor confirming it in their calling app.
- The home hero lazily loads Three.js and builds a lightweight, interactive architectural massing scene in WebGL. Pointer movement subtly adjusts the view; the scene pauses off screen. The main “Building your vision” headline lifts briefly when clicked and can also be activated with Enter or Space. The existing house photograph remains as the visual fallback if WebGL or the Three.js CDN is unavailable.
- The **Top Pick · Interactive 3D House Designer** offers a live browser-built Modern Courtyard, Contemporary Villa, or Traditional Gable concept. Visitors can rotate/zoom, change exterior colour, render finish, roof material, glazing, floor count, and daylight/evening lighting, then reset or save a text brief. The model reframes responsively and its controls are grouped for easier use. This is an illustrative concept, not a construction drawing or completed SAFA project.
- In the 3D house designer, visitors can load a browser-supported local image up to 25 MB. It appears immediately on a framed 3D surface in the viewer, which can be dragged to rotate; clicking the image can sample a colour for the editable house concept. This is a 3D display of the original photo, not a reconstruction of the scene's geometry or hidden sides. Image decoding and formats depend on the visitor's browser; the file stays local and is never uploaded.
- Each of the 13 **SAFA Innovation Studio** cards opens its own addressable page under `tools/`, with a back link and a direct switcher to every individual tool. The conceptual floor-plan workspace draws editable room blocks and exports SVG/JSON; material choices can launch the 3D house with the selected exterior tone, roof, or glazing; the SAFA AI tool opens the multilingual text chat; and the project gallery uses the available illustrative assets. City-zone, sketch-preview, cutaway schematic, user-entered price comparison, moodboard, and project-discussion draft tools are interactive and animated. The digital twin and admin pages clearly state that a secure backend and private records are not configured. These pages do not claim AI-generated floor plans/images, surveyed city data, live supplier prices, structural cutaway models, customer records, or an official proposal.
- Every Innovation Studio card includes a distinct visual preview and its own **Preview here** button. Each button opens a real Three.js 3D concept scene in the on-page modal; visitors can drag or use keyboard arrows to rotate and zoom, then change the feature's controls and see the 3D model update. The scenes include editable floor blocks, house finishes/styles/floors, text assistant, gallery panels, city blocks, a local sketch display, cutaway layers, quote bars, sample twin stages, moodboard swatches, a proposal sheet, journey nodes, and an admin dashboard concept. Sketch files remain local to the browser; project proposal drafts can be downloaded locally. The separate **Open this tool** link still navigates to its dedicated page. Models are clearly labelled concepts and do not imply that an unconfigured AI, map, supplier, customer-data, or structural 3D service is live. Reduced-motion settings pause the ambient 3D animation while preserving interactive controls.
- The normal customer navigation does not expose [SAFA Future Lab](./tools/future-lab.html). Public users can freely use the website without sign-in. Administrators use the private protected login route to enter the authenticated admin interface and access the lab. Each feature has its own page, shared responsive styling, browser 3D concept, direct links back to the lab and the original 13 tools, and feature-specific controls. House/room scenes can be rotated and zoomed; local briefs and checklists are not uploaded. The lab explicitly identifies the absent VR hardware, AI/OCR, project database, sensor, supplier, and customer-submission integrations instead of simulating their results. Routes and verification notes are listed in [FUTURE-LAB-VERIFICATION.md](./FUTURE-LAB-VERIFICATION.md).
- In the **Top Pick · Interactive 3D House Designer**, the **Customize your 3D model** panel accepts self-contained `.glb` models up to 30 MB. The selected file is read locally in the browser, fitted to the viewer, and never uploaded. Visitors can recolour the entire model or individual mesh parts, change the displayed surface finish, restore original materials, remove the custom model, and save a local design brief. Existing geometry and UVs remain intact; this changes visual materials rather than remodeling geometry. Separate `.gltf`, `.obj`, `.fbx`, `.stl`, linked external textures, and models without editable mesh surfaces are not supported. The built-in SAFA model remains available when the uploaded model is removed.

### Preview and deploy

Open `index.html` in a browser to preview the intro and the static website. The intro appears once per browser tab session; reloading that tab does not replay it. Use **Skip intro** to leave it, or **Replay SAFA introduction** at the footer to play it again. Add `?replayIntro=1` to the URL to replay it on demand, or `?openAssistant=1` to open the assistant directly. In the 3D house designer, upload a browser-supported image up to 25 MB to display it on a rotatable 3D surface; click the photo preview below to sample a colour for the house concept. This displays the original image in 3D but does not reconstruct a full 3D scene. For the interactive 3D scenes and secure SAFA AI endpoint, preview or deploy through the existing Vercel project; the website loads Three.js from its configured CDN, and AI/chat setup is described below. The cinematic intro always attempts to play its music. If the browser blocks autoplay, the visual intro still plays and offers **Play intro with sound** as a retry. Separate interface sound effects are off until a visitor explicitly enables them; the UI sound toggle affects those short navigation and control tones only, not the intro music.

## SAFA AI

The chat widget includes:

- A Vercel serverless endpoint at `api/chat.js` for multilingual construction guidance.
- A multilingual text chat interface with language selection and auto-detection for typed messages.
- A command registry in the existing assistant for approved page navigation, WhatsApp, language changes, repeat/stop, and close commands. English, Tamil, Hindi, and Malayalam command patterns are included.
- The Contact section’s **Chat with us** action opens SAFA’s direct WhatsApp chat with a short enquiry message ready to send; it does not send the message automatically.
- The SAFA AI chat is text-only. Microphone input and spoken replies have been removed; the typed language selector and AI auto-detect option remain.
- A typed website-guide fallback for English and Tamil when the secure AI endpoint is unavailable.
- A non-character animated logo fallback for assistant states. A licensed 3D architect model has not been provided.

### Admin-only Innovation Studio and Future Lab

The 15 SAFA Future Lab pages are restricted on the Vercel deployment by Routing Middleware and an eight-hour, signed, HTTP-only admin session. The public homepage, normal customer navigation, and public website remain separate from the admin interface. The authenticated admin interface provides access only to the SAFA Future Lab hub and its individual features; it does not expose a separate customer account system or project records. The chat and speech API endpoints require an authenticated admin session. Only `safaconstruction62@gmail.com` is accepted as the admin email.

Before deploying, add these server-side environment variables in the Vercel project's **Settings → Environment Variables** for every environment where the tool should work:

- `SAFA_ADMIN_PASSWORD` — choose a unique password with at least 14 characters; do not put it in source code or share it in chat.
- `SAFA_ADMIN_SESSION_SECRET` — a private, randomly generated secret of at least 32 bytes. Keep it separate from the password.

Deploy the project after setting the variables. Protected Future Lab URLs redirect unauthenticated visitors to the private admin-login route and return the administrator to the requested tool after sign-in. Use `safaconstruction62@gmail.com` with the separately configured password, then use **Sign out** to end the admin session. Keep the password in Vercel environment variables only, never in source code or documentation. Apply a Vercel Firewall rate limit to `/api/admin-login` as an additional password-guessing safeguard. If the variables are missing or invalid, access fails closed. Directly opening the static files with `file://` does not provide server-side login; test this feature on the configured HTTPS Vercel deployment.

### Deploying the AI endpoint to Vercel

1. Import or redeploy the project on Vercel. The `api/chat.js` file is automatically available as `/api/chat`.
2. In the Vercel project's **Settings → Environment Variables**, add `OPENAI_API_KEY` using a server-side API key. Do not place this key in `index.html`, `script.js`, or any `NEXT_PUBLIC_`/client-side variable.
3. Optionally add `OPENAI_MODEL` to select a model available to the account. The default is `gpt-4o-mini`.
4. Set provider spending limits and use Vercel's platform protections/rate controls before publicly advertising the endpoint.

Without the OpenAI key, `/api/chat` returns a configuration notice and the widget falls back to the limited website guide. Opening `index.html` directly with `file://` cannot access the serverless endpoint.

### Text chat language support

The searchable language selector lists languages the AI endpoint can be asked to answer in and includes AI language detection for typed messages. When the chat endpoint is configured, the current message and recent conversation are sent to the AI provider. Visitors are warned not to enter sensitive details. The website-only fallback is limited to English and Tamil. Cost guidance asks for missing project details and clarifies that estimates are preliminary and depend on location, materials, labour, structural design, and site conditions.
